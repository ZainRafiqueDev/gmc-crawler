# Real-world validation set (accuracy scoring)

Answers "how accurate is this tool, really?" with per-category precision/recall
against human-determined ground truth - not a single blended percentage, and
not ground truth generated by asking an LLM to guess (that would just be
testing the tool against itself).

## How it works

1. Copy `validation_set.template.json` to `validation_set.json` (gitignored -
   it will name real stores).
2. Pick 5 real stores you're authorized to audit. Mixed platforms ideally:
   at least one WooCommerce, one Shopify, one custom/unknown-platform store,
   and ideally at least one clean store and one with known real issues.
3. For each store, manually look at the live site and fill in a `pass`/`fail`/
   `not_applicable` verdict (plus a one-line evidence note) for each of the 8
   categories in `category_mapping.py`. This is the ground truth - it has to
   be yours, from actually looking at the site.
4. Run `python -m validation.score_validation`. This runs the exact same
   pipeline as `audit.py` (`app.graph.run_audit`) against all 5 stores, maps
   the resulting findings to the same 8 categories, and prints a per-category
   TP/FP/TN/FN/precision/recall table plus a list of every disagreement.
5. Raw per-store findings are saved to `validation/results/` (gitignored) so
   a disagreement can be inspected without re-crawling.

## Why per-category, not one number

A single blended accuracy number hides which categories are actually weak.
"92% accurate" could mean 8 categories all fine, or 7 perfect and one
(e.g. `product_price_availability_accuracy`, the hardest category - it
depends on live cart/checkout behavior) badly wrong. Precision/recall per
category surfaces that; a blended score wouldn't.

## Notes on the tool-verdict logic

A category counts as `fail` from the tool's side if any finding in it has
confidence `confirmed` or `potential_risk`. If every finding in a category is
`cannot_verify` (e.g. no LLM API key configured, so `policy_substance_quality`
and `prohibited_content_risk` can't run), that store/category pair is
excluded from scoring rather than counted as a miss - see
`tool_verdict_for_category` in `score_validation.py`.
